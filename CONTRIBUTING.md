# Contributing

The rules for working in this repo. [QUICKSTART.md](QUICKSTART.md) covers
setup.

## Components

- `codex-gate/` is **frozen at 0.3.1**: it is the plugin in daily use. Don't
  change it unless Adam asks for a fix. It is not linted or type-checked; its
  tests still run.
- `pr-lifecycle/` is the next major version. New work goes here.
- **Never load both plugins at once.** Both register `/pr-gate` and hold PR
  creation, so two would gate the same PR twice.

## Code style

- Hand style: no semicolons, single quotes, lines up to about 160 columns.
  `npm run lint` checks it on `pr-lifecycle/`; long prompt text inside
  strings and template literals is exempt from the line limit.
- **Never run a formatter** (Prettier or similar) or `eslint --fix`. Fix lint
  findings by hand, surgically.

## Generated files

`.claude-plugin/types/` in each component is generated by the harness and
gitignored. Never commit it.

## Versions

When a component's version changes, bump its `.claude-plugin/plugin.json`,
the version line in its README and the table in the root README together.
There is no `VERSION` file.

## Commits and pull requests

- End commit messages with a `Co-Authored-By:` line for the model that
  helped, if one did.
- PRs to `main` go through `/pr-gate` first: `gh pr create` is held until the
  pre-PR Codex gate finishes. Fill in the PR template.
- CI (the `check` job) must pass before merge.
- CodeQL (`codeql.yml`) scans TypeScript and the workflows on PRs, pushes to `main` and weekly; Dependabot opens weekly update PRs for npm dev dependencies (grouped) and actions.

## Checks

From the repo root, after `npm ci`:

```bash
npm run lint       # eslint, pr-lifecycle only
npm run test       # claude plugin test, both components
npm run validate   # claude plugin validate, both components
npm run typecheck  # tsc -p pr-lifecycle --noEmit, with the pinned TypeScript
npm run check      # all four
```

The repo pins its own TypeScript, so `npm run typecheck` replaces the old
cookbook `tsc` path; don't use a bare `npx tsc` outside `npm run`.

`typecheck` needs `pr-lifecycle/.claude-plugin/types/`, which the harness
writes only when a Claude Code session loads the mod from that checkout.
In a fresh clone, load it once (see QUICKSTART) before running it. CI has no
session, so there it skips typecheck with a warning.
